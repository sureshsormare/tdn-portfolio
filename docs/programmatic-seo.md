# Programmatic SEO model

How the site turns a trade dataset into thousands of indexable pages without a database in the request path.

## Page families and URLs

| Family | URL pattern | Source file(s) under `data/` |
|---|---|---|
| Product hub | `/pharmaceutical/<product>/` | `product-insights/<product>.json`, `product-supplier-details/`, `product-countries/` |
| Product trade route | `/pharmaceutical/<product>/<trade-route>/` | `import-routes/<route>.json` or export route files |
| Product buyers | `/pharmaceutical/<product>/buyers/`, `/buyers/<buyer>/`, `/buyers/all/` | `product-buyer-details/` |
| Supplier profile | `/supplier-profile/<company>/` | `company-profiles/` |
| Buyer profile | `/buyer-profile/<buyer>/` | `company-profiles/` |
| HS code | `/hs-code/<code>/` | `hs-codes/`, `hs-code-details/`, `hs-codes-master.json` |
| Country | `/countries/` and country sections on product pages | `countries/` |
| Editorial | `/blog/<slug>/`, `/author/<slug>/` | `authors.json`, `author-assignments.json`, blog content |

Slugs are produced by `lib/canonical-product-name.ts` and country normalisation in `lib/country-normalization.ts`, so the same entity always has one URL. Trailing slashes are canonical; the middleware redirects the bare form.

## Precompute pipeline

`scripts/precompute-*.ts` read the trade database once and write one JSON document per page. Long runs are shardable (`--shard N --total M`, `--batch K`) and resumable (`START_BATCH`). Insight text for products, suppliers, buyers, routes and HS codes is generated by `scripts/generate-*-insights.ts` and stored alongside the numbers, so the page never calls a model at request time. Company profiles are assembled by `scripts/build-company-profiles.ts` from supplier and buyer aggregates.

## Rendering

Pages are React server components that read their JSON and render tables, d3 charts (trade flow, sankey, treemap) and structured data. With `DB_DISABLED=1` the database helpers return empty results instead of connecting, which is how the site runs without MongoDB.

## Images

Each product, supplier, buyer, HS code and country page has a generated share image (`.webp`) used as `og:image`, in JSON-LD `ImageObject` and in the image sitemap. Images are produced offline with `sharp` and uploaded to object storage. `lib/image-paths.ts` emits same-origin paths (`/pharmaceutical/<product>/<product>-india-export-import-intelligence.webp`); `next.config.ts` rewrites those paths to `ASSET_ORIGIN`, so image URLs stay on the site's domain while the bytes come from storage.

## Sitemaps and discovery surface

- `sitemap.ts` (per family), `sitemap-priority.xml` (products with video first), `image-sitemap.xml`, `news-sitemap.xml`, `sitemap-video.xml` (from the product video map in storage), `blog/rss.xml`, `llms.txt` for AI crawlers.
- The admin console submits sitemaps and requests indexing through the Google Indexing API, and inspects URLs with the Search Console URL Inspection API (`app/api/index-check`, `request-indexing`, `submit-sitemap`).
- `lib/valid-links.ts` maintains the list of URLs that exist, shared with the SEO agent so published posts never link to a missing page.

## Crawler analytics

`middleware.ts` flags crawler traffic and forwards the user agent, IP and path as headers; `lib/crawler-tracker.ts` identifies the bot (including IP-range identification for generic bots), buffers visits and flushes them to storage as one JSON file per day. The `/admin/crawlers` pages summarise visits per bot, per day and per path, which is how indexing progress is monitored without third-party analytics.
